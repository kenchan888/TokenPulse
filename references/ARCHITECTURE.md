# TokenPulse 内部结构

> 面向维护者。用户向说明在 `SKILL.md`，排障在 `TROUBLESHOOTING.md`。
> 改口径、改判定、改版式之前先读这一份，里面每条数值都是实测出来的。

---

## 1. 两套统计口径

一套判据，两个时间窗。**单窗口**看"界面正在显示的那个会话文件"，**今日**看"全部会话文件里今天那一段"。

### 1.1 单窗口（底部浮条四项）

范围：只读当前界面显示的那一个 `~/.workbuddy/projects/<目录>/<uuid>.jsonl`。时间窗无，跨天不清零，切会话整体重算。

| 项 | 字段与算法 |
|---|---|
| `对话N轮` | 按 `conversationRequestId` 聚合后计数；一轮里分几步输出仍算 1 轮 |
| `消耗X.XX分` | `Σ providerData.rawUsage.credit`，两位小数 |
| `Token总计` | `Σ rawUsage.total_tokens`（输入 + 输出，每次调用都算） |
| `缓存命中XX.X%` | 全局 `Σ prompt_cache_hit_tokens ÷ Σ prompt_tokens`；逐条算完再平均会失真 |

**算一轮的五个条件（同时满足）**

1. 该请求**最后一条**记录是 assistant 消息——后面还跟着工具调用就说明没结束；
2. 带 `providerData.usage`；
3. `providerData.error` 为空；
4. 未被 `resend-fork-notice.editedUserItemId` 作废（回退 / 编辑重发会让整个请求失效）；
5. 不是纯子代理请求。

**不算轮但钱照算**：用户中断（`error.message = "Interrupted by user"`，常伴 `skipRun`）、回退重发、上下文压缩摘要、自动取标题、后台子代理。

**算一轮**：`@skill` 唤起，它就是一条正常用户消息。

**未落定**：最后一条仍是 `function_call` / `reasoning` → 先不算，落盘后 0.15 秒内补上。

判定看"请求的最后一条记录"，不是"有没有出现过 usage"：同一请求中间某步带 usage、后面还跟工具调用的，说明这轮没结束。

**读盘**：文件 ≤ 64MB 整份读（`FULL_MAX`）；更大退化只读尾部 24MB（`TAIL_BYTES`）。增量读只吃到最后一个完整换行，正在写的半行留到下次。文件变小或被重写 → 归零全量重读。`Reader.set_path` 换会话时统计清零。

**节奏**：空闲 0.25 秒一轮，最近 3 分钟内有调用时 0.15 秒。

### 1.2 今日汇总（侧边栏三列）

同一套轮 / 钱 / token 判据，只换时间窗与文件范围：`~/.workbuddy/projects/**/*.jsonl` 全部会话 + 各自的子代理日志。

磁盘上其实是两层，扫描必须两层都进：

```
projects/<项目>/<会话ID>.jsonl                        ← 会话正文
projects/<项目>/<会话ID>/subagents/agent-*.jsonl      ← 子代理，钱只写在这里
projects/<项目>/<会话ID>/tool-results/*.ndjson        ← 工具原始返回，不算钱，别进
```

**子代理的花费只存在于 `subagents/agent-*.jsonl`**：主会话文件里 `isSubAgent` 记录实测为 0 条，所以漏扫这一层，今日消耗就整整少掉子代理那一笔（实测差过 9.74 分 / 43.8 万 token）。会话目录下还有 `tool-results/`，下钻时只认 `subagents`、`agents` 两个名字。

| 项 | 口径 |
|---|---|
| 时间窗 | 本地日界 `今天 00:00 ~ 现在`，**按记录自身的 `timestamp` 归日**，不看文件 mtime、不看会话创建时间 |
| 文件范围 | 只扫 mtime ≥ 今天 00:00 前 2 分钟的文件，省 IO；漏扫窗口靠账本兜 |
| 消耗 | 所有会话 + 子代理的 `Σ rawUsage.credit`；中断、回退、压缩、取标题都算 |
| Token | 所有文件的 `Σ rawUsage.total_tokens` |
| 轮 | 同五条件，跨文件求和；纯子代理不算轮 |
| 命中率 | 全局 `Σhit ÷ Σprompt`；分子分母必须在同一条记录里都有才计入，否则会算出 >100% |

**四条红线**

1. **同一笔钱只记一次**：`credit-usage`（`source=team_member`）与 `subagents/agent-*.jsonl` 里的 `rawUsage` 是同一笔钱的两种记账，不能相加，以带 `rawUsage` 的一侧为准。
2. **跨零点拆开归日**：钱按每条 `rawUsage` 各自归日，轮按请求**完成时刻**归日 → 各日之和 = 全量，不丢不重。
3. **今日账本按会话记账，只增不减**：`_tmp/spend-<日期>.json` 存当天每个会话的 `[轮, 分, token, prompt, hit]`，每轮扫描后与内存值**逐项取最大**再落盘（8 秒节流）。
   - 会话在界面上被删掉后，日志文件即便消失，那一笔钱仍是真花掉的，今日合计**不回退**；重启后从账本续上。
   - 跨天时账本换文件，只保留最近 7 天。
   - 这个文件在 `_tmp/` 下，不参与打包、可以随时删（删了只是丢掉"已删会话"的历史那部分）。

命中率**不上界面**：与底部条同屏两个命中率会让人误解，且按 token 量加权后日维度没有决策价值。

## 2. 数据来源

| 来源 | 取什么 |
|---|---|
| `~/.workbuddy/projects/<会话目录>/<uuid>.jsonl` | `rawUsage.credit / total_tokens / prompt_tokens / prompt_cache_hit_tokens`；`conversationRequestId`；`usage` + 末条类型；`error`；`resend-fork-notice.editedUserItemId` |
| `~/.workbuddy/logs/daemon.log` | 最后一条 `history-probe {"conversationId":…}` |
| `~/.workbuddy/logs/renderer.log` | `heartbeat appState {…"currentConversationId":…}` |
| `~/.workbuddy/workbuddy.db` | `sessions` 表，按 `max(last_activity_at, updated_at)` 倒序 |

`timestamp` 是**毫秒**整数，当秒用会算错归日。
`rawUsage` 在**每一次模型调用**上都有（含工具调用那几步），只读 `message.usage` 会漏掉约 97% 的 token。

## 3. 挂哪些窗口 / 每个窗口跟哪个会话

**窗口筛选**：类名 `Chrome_WidgetWin_1` + 标题含 `WorkBuddy` + **进程名为 `workbuddy.exe`** + 尺寸 ≥ 400×300 + **有最小化按钮**（`WS_MINIMIZEBOX`）。

后两条都不能省：

- **最小化按钮**：设置面板是独立顶层窗口，同进程、同类名、标题也是 `WorkBuddy`、同样没有 owner，尺寸也不小，靠前三条分不出来。唯一的稳定区别是 style——主窗口 `0x14C70000`、设置面板 `0x14C50000`，差的就是最小化位（Electron 里 `minimizable:false` 就没这一位）。每轮还会反向清理：挂在辅助窗口上的条子直接拆掉。
- **进程名**：浏览器打开 `open.workbuddy.cn` 时，窗口标题是「WorkBuddy 开放平台 … - Microsoft Edge」，类名同样是 `Chrome_WidgetWin_1`，也有最小化按钮，尺寸也够——前几条全中。不比对 `workbuddy.exe`，浏览器窗口会被当成第二个 WorkBuddy，多挂一条条子，还会把今日面板画到浏览器界面上（侧边面板跟着"当前前台窗口"走，前台恰好是浏览器）。进程名用 `QueryFullProcessImageNameW` 取，拿不到时退回前几条判断，不会整块失效。

**会话跟随三级信号**

| 优先级 | 信号 | 频率 | 用途 |
|---|---|---|---|
| 1 | `daemon.log` 的 `history-probe` | 每显示一个对话就出现 | 主用：界面每显示一个对话就探它的历史 |
| 2 | `renderer.log` 的 `heartbeat appState.currentConversationId` | 5 秒一条 | 备用：日志轮转或格式变了时兜底 |
| 3 | `sessions` 表按 `max(last_activity_at, updated_at)` 倒序 | 2 秒 | 最后兜底 |

切对话 0.25 秒内换数，**不需要发消息**。多窗口时只有前台窗口跟随界面，其它保持各自绑定，免得两条条显示同一个数字。想钉死用 `TP_SESSION`。

**空白新任务**：`history-probe` 里 `persisted:false` 且日志未落盘 → 直接判非对话页，不用等像素。这类页面显示 `对话0轮 · 消耗0.00分 / Token总计0 · 缓存命中0%`。

**已知边界**：两个窗口并排各自显示不同对话时，probe 会交替出现，无法分辨此刻在看哪个；前后切换（单窗口）完全准确。

## 4. 显示还是隐藏

**两道闸门，顺序不能颠倒**：

1. **前台闸门**：`wb_in_front(owner)` 比对前台窗口与 WorkBuddy 窗口的进程 id。不在前台 → 条子 `park()`、面板 `park()`，本轮结束。所有抓屏判定都在这一道之后，因为非前台时 `BitBlt` 抓到的是别人的界面像素（浏览器页面的横条会被当成账号灰线，页面的浅色块会被当成"展开的列表"），据此判断会得出完全错误的位置和结论。
2. **页面闸门**：前台但停在六个入口页 → 也收起。判据见下。

**不变量**：WorkBuddy 侧边栏任何时刻**恰好一行**处于选中高亮。整套判定建立在这一条上。

| 界面 | 高亮位置（DIP，150% 缩放） |
|---|---|
| 六个入口页 | `96~130 / 132~166 / 168~202 / 204~238 / 240~274 / 276~310`（步距 36、行高 34） |
| 某个对话 | 「最近」列表里的那一项，第一项 `364~398`；「最近」标题在 `~348` |

**判据只有一条**：分界 `SB_NAV_SPLIT_DIP = 340`。高亮在线上 → 入口页（收起）；在线下 → 对话页（显示）。不记点击、不记悬停、不看文案，所以**重启后第一帧就能判对**。

### 4.1 扫描

- 横向只扫侧边栏靠左那一窄条 `8~70 DIP`（`SB_SCAN_X0_DIP` / `SB_SCAN_W_DIP`）。入口行高亮是整行铺满的，窄条一样认得出。扫整条 300 DIP 的话，随便一个记事本盖住右半就"看不懂"，条子会停在旧状态。
- 纵向 `84~620 DIP`（`SB_NAV_TOP_DIP` / `SB_SCAN_BOT_DIP`）。上沿必须留在「新建任务」行上沿（96）**上方**：正好压在 96 时那块高亮贴着带子上沿，会被"贴边=被切过"的规则丢掉。
- 逐行判：每 2 DIP 一行、每行抽 40 列；与全带众数（底色）差 ≥ `SB_DEV = 7` 灰阶的列**超过 60%** 就算这行是亮的。用占比而不是中位数——文字行只有少量列是墨色，占比上不去。
- 连续 ≥10 DIP、整块高度落在 `SB_ROW_MIN_DIP = 18 ~ SB_ROW_MAX_DIP = 52` 才算一块。高度窗口专挡头像弹层：那块「套餐 / 积分余额」面板几百 DIP 高，整块超出窗口，不会被当成"某行选中"。
- 实测配色：侧边栏底 247、高亮 235（差 12）、弹层白面板 255（差 8）。门槛 7 卡在中间。

### 4.2 悬停四情形

hover 与选中同色，像素分不出来，所以改看鼠标位置：

| 情形 | 高亮块 | 结论 |
|---|---|---|
| 对话页，鼠标扫过入口行 | 入口块在鼠标下，历史块不在 | 显示 |
| 入口页，鼠标停在刚点的入口行 | 入口块在鼠标下，无历史块 | 收起 |
| 入口页，鼠标停在别处 | 入口块不在鼠标下 | 收起 |
| 回对话页时，鼠标扫过入口行 | 两块都不在鼠标下（过渡帧） | 不动（防闪） |

最后一情形是过渡保护：正常界面不会同时出现"入口区一块 + 历史区一块"都不在鼠标下，那只能是悬停高亮还没淡掉的一帧。

带子里**只有鼠标压着的那一块**时，压 `SB_HOVER_HOLD_S = 0.45` 秒再认。

### 4.3 两个加速器

- **点在入口行**（横向在侧边栏内、纵向落在入口行段）：记 `nav_click_t`，0.5 秒内一律按入口页处理，不等重绘。
- **连续两帧判"入口页"**（0.15 秒）才收，躲开切换动画的单帧假象；有点击记录时立刻收。

点击检测用「任何线程读到左键按着就记时间戳」找上升沿：`GetAsyncKeyState(1) & 1` 在本机注入点击时不置位，几何线程 20 ms 一轮还会先把低位读走；人手一次点击 80~120 ms，20 ms 轮询稳拿。

### 4.4 保护

- `WindowFromPoint` 在扫描区取 9 点确认还属于本窗口；被别的程序盖住就返回"判断不了"、保持上次结论。
- 返回 `None` 时冻结横向几何，防止弹层糊住侧边栏右缘时条子凭空右移。
- 扫描区超出窗口边界（侧边栏折叠等）→ 不猜。
- **底部基准防呆**：「内容由 AI 生成…」永远在窗口底往上 17~25 DIP；量出 6~34 DIP 之外、或相对上次突变 >12 DIP，都当成"这页没有那句话"不采用（定时任务这类没有输入框的页会让整条凭空上移 25 DIP）。

排障开关：`scripts\` 下建 `_trace.flag`，`_trace.log` 会逐帧记 `v= / bands= / cur= / rect= / left=`（`v=True` 对话页、`False` 入口页、`None` 判断不了）。查完删掉。它走 `_traw()` 直写，不过 `log_err` 的 30 秒去重。

## 5. 位置与外观

整条横跨内容区，两段文字各自贴两端，中间给提示文案留空。

- **左段**：从「侧边栏右缘 + 7 DIP」起（`SIDE_GAP_DIP`）。
- **右段**：右对齐到窗口右缘减 `TP_RIGHT`（默认 6 DIP）。
- **下**：不写死。每次排版量「内容由 AI 生成，请核实重要信息」的**墨迹竖直中心**，把浮条摆到两者中心重合。中等窗口 / 最大化 / 全屏三种模式该文案离底距离不同，写死必然有一种错位。
- **侧边栏右缘探测**：取窗口底往上 180 / 480 DIP 两条 1 像素横带（相距 300 DIP），各自把 `x±4px` 绿通道差 ≥8 的列记为阶跃；两行都能在 ±3px 内命中的 x 才算数，取最左那个 + 7 DIP。只看阶跃不看颜色方向——侧边栏有时浅灰有时纯白，内容区还可能被遮罩压暗。
- **读数变了不等于侧边栏变了**：差 >0.8 DIP 时，只有「左键按着且指针在候选边界 ±14 DIP 内」或 `edge_relearn`（窗口尺寸刚变）才采纳，否则沿用旧值。这条专治点头像弹出的账号面板——那块白面板比侧边栏宽 15 DIP，两条横带都能测到它那条硬边。
- **宽度保护**：左段右缘不得越过提示文案左边界（中心 − 95 DIP − 16 DIP 留白），右段同理。装不下按档降级：` · ` → `·` → 只留「对话N轮」；右段退到只留「Token总计」。两段文字与提示文案必须互不重叠。

**透明浮字的画法**：所有内容按 4 倍尺寸画进掩膜 DIB → `SetStretchBltMode(HALFTONE)` + `StretchBlt` 缩回 1 倍 → `alpha = 覆盖率^0.9 × 0.70`，字色纯黑、RGB 保持 0（预乘）。HALFTONE 对 32bpp 走加权平均，比 GDI 在 12 px 下直渲染干净得多。不用 ClearType：子像素彩边在透明底上会变成红蓝毛边。

**遮挡排除**：`above_rects()` 沿 z 序只取 owner 之上的窗口，矩形外扩 `OCCLUDE_DIP = 22` 整段排除——必须按矩形算，DWM 阴影画在窗口矩形*外面*，`WindowFromPoint` 会认为那块属于我们。候选边还要过 `EDGE_SHARP = 7` 的硬边关：真分界线是一个像素内的硬跳变，阴影和遮罩是每像素 1~3 灰阶的软坡。都过不了就返回 `None` 沿用上次值，冻结比乱跑好。

## 6. 今日面板

侧边栏底部、账号行上方的一小块浮字，只画字不画底，与浮条同一套墨色管线。

```
今日对话        今日消耗        今日Token      ← 标签在上（浅灰）
   10轮         215.89分         65.82M      ← 数字在下（深灰）
```

### 6.1 常量

| 常量 | 值 | 含义 |
|---|---|---|
| `TODAY_W_DIP` | 256 | 默认内容宽，实际值由 `today_panel_w()` 按侧边栏实时算 |
| `TODAY_MIN_W_DIP` / `TODAY_MAX_W_DIP` | 150 / 460 | 宽度下限（三列不压字）/ 上限（防异常读数） |
| `TODAY_H_DIP` | 62 | 面板高 |
| `TODAY_GAP_L_DIP` | 12 | 距侧边栏左缘 |
| `TODAY_PAD_B_DIP` | 10 | 数字底边距面板底（= 距灰线） |
| `TODAY_GAP_B_DIP` | 57 | 兜底值，正式值由 `find_account_sep()` 动态测 |
| `TODAY_V_DIP` / `TODAY_U_DIP` / `TODAY_L_DIP` | 18 / 11 / 13 | 数字 / 单位 / 标签字号 |
| `TODAY_GAP_VL_DIP` | 6 | 标签与数字行距 |
| `TODAY_GAP_VU_DIP` | 3 | 拉丁单位（M / K）与数字的间距 |
| `TODAY_GAP_VU_CJK_DIP` | 2.5 | 中文单位（轮 / 分）专用 |
| `TODAY_INK_NUM` / `TODAY_INK_LBL` | 255 / 180 | 数字深灰（`PANEL_TABLE` 满墨 0.90 ≈ #181818）/ 标签浅灰（#545454） |
| `TODAY_POLL_S` | 5.0 | 扫盘周期 |

**中文单位为什么要单独收紧**：汉字字面自带左侧留白，同样 3 DIP 下「分」的墨迹间隙比 M 大。2.5 是逐像素实测的结果——mass 口径（该列 ≥2 行有墨才算实心边）下 M 恒为 6 px，CJK 取 2.5 时也是 6 px。2.0 是 5 px（偏紧），3.0 偏大；2.25~3.0 区间里 2.5 与 2.75 同落 6 px 平台，取中点抗亚像素舍入。

### 6.2 版式

三列：左列贴左、中列精确居中（`w/2`）、右列贴右（右缘留 1 DIP 抗锯齿余量），`today_anchors(w)` 返回 `(0.0, w/2.0, w-1)`。**标签与数字共用一个左起点**（「今」对准数字首位），整组再按左/中/右锚定——各列独立居中时，数字块更宽会向左溢出。单位按**基线**与数字对齐。

深灰数字走单独的 `PANEL_TABLE`（`rebuild_ink_table()` 里和 `INK_TABLE` 一起建，满墨 0.90，比浮条的 0.70 深）。

**宽度跟着侧边栏走**：`today_panel_w()` 拿状态条的 `left_dip`（侧边栏右缘 + 7 DIP）反推侧边栏宽，面板宽 = 该宽 − 24 DIP，下限 150 DIP（再窄三列就要压字）。宽度变化 ≥ 2 px 就 `resize()`：重建 DIB、清签名逼下一轮重绘，三列锚点按新宽度重新分配，所以拖动侧边栏时三列始终是「贴左 / 居中 / 贴右」。写死 256 的后果：拖窄后第三列跑到对话区上，拖宽后三列挤在左边一小块。

**z 序**：`SetWindowPos(hwnd, HWND_TOP, …)` 并每 0.25 秒重提一次（`_z_t`）。只在 WorkBuddy 前台时才会被调用，所以不会压到浏览器等别的程序上；重提是为了解决"沉下去就不上来"——附属窗口一旦被压到 owner 之下，位置没变就不再调 `SetWindowPos`，切回 WorkBuddy 也看不见。**不要用 `HWND_TOPMOST`**，那会让面板变成独立浮窗，切到任何程序都盖在上面。

### 6.3 灰线动态检测

账号行上方那条灰线距窗口底**不是常数**，窗口化实测 56.7 DIP，切全屏/最大化还会浮动。`find_account_sep(r)` 从窗口底往上扫侧边栏左缘 256 DIP 宽、110 DIP 高的一小块，找「灰像素（灰度 195~240）占比 > 55%」的行；候选必须落在 40~80 DIP（`valid_sep`），且连续两次读数差 ≤ 1.2 DIP 才采纳。

- rect 一变进 1.2 秒动画期，每 0.05 秒测一次但先不采纳，连续两次一致通常 0.1 秒内定案；
- 静止后 2 秒复核；扫不到或读数离谱就维持原值（初值 57）。

尺寸切换时**不强制收起面板**：`place()` 每轮按当前 rect 重算，0.05~0.1 秒就到位；只在 rect 变化后 `TODAY_OBSC_FREEZE_S = 0.6` 秒内冻结遮挡判定，防止全屏动画中滑过面板区的列表行被误判成弹层。

### 6.4 遮挡即隐藏

账号菜单弹层、展开的「最近」列表会把面板顶掉。`today_obscured(r, panel)`：

- 一次抓下整块面板区 + 顶上 8 DIP 保护带，只复用一块 DIB；
- 面板自己画的字用它的 **alpha 通道挖掉**（`obsc_foreign(..., alpha)`），否则会把自己当成列表文字；
- 底色按像素**众数现算**，不写死底色值，也不用"够白就算弹层"的单阈值；
- 在保护带 / 标签 / 数字 / 数字下方各取几条细横带，非底色像素占比 > 1.5% 即命中；
- **别的程序压上来时不判遮挡**：`external_window_rects()` 枚举其它进程的可见顶层窗口（排除 WorkBuddy、本进程、`EXT_WND_SKIP_CLASSES` 里的系统壳层、自己的面板类），矩形外扩 `EXT_WND_MARGIN_DIP = 12`；任一与扫描区相交就跳过本轮判定。侧边栏有透明区，后面窗口的文字和投影会把众数底色带偏。
- 命中立刻 `park()`，连续 3 帧（约 0.09 秒）干净才恢复（`obsc_step` 滞回）。

横带定义是 `(起点DIP, 高度DIP)`，由 `obsc_band_ranges()` 转像素区间——第二个值是**高度**不是终点。

面板与条子共用同一道**前台闸门**：WorkBuddy 不在前台就 `park()`。在前台时不受"是否对话页"影响，常显在侧边栏底部（代价是盖住侧边栏底部一小块）。

### 6.5 空态

今天一笔都还没有（或首批扫描没回来）时整块不露脸，不显示 `0轮 0.00分 0.00M`。判据 `today_empty(vals)`，判空时顺带清 `sig`，等有数了必定重绘。

### 6.6 两条线程

| 线程 | 干什么 | 节奏 |
|---|---|---|
| `today_poll_loop` | 只算数：枚举今天的 jsonl、增量读、出 `{n, credit, tok}` | 5 秒 |
| `today_loop` | 只碰窗口：抽消息、建窗、跟手、按需重绘 | 30 ms |

扫盘不许进窗口线程——一轮冷启动要读几十 MB，窗口线程一卡就被 DWM 判「未响应」，盖黑框。

## 7. 改代码前必须知道的七件事

1. **跟随与重绘是两条独立路径**。`follow_loop()` 只搬窗口、碰位图；每条浮条自己的 `tick()` 每 0.6 秒刷数据、按需重绘。把 `SetWindowPos` 塞回数据循环，跟手度会掉到 200 ms 级。
2. **自适应轮询**：跟随线程静止 12 ms 一次、检测到位移切 2 ms、停手 0.6 秒回落；几何线程每 50 ms 读一次窗口 rect ＋看一眼左键，尺寸一变立刻抓屏重排，所以切全屏 20~50 ms 内就位。鼠标按着时 60 ms 抓一次屏（抓一次 4~6 ms，盲抓会吃到 10% CPU）。
3. **坐标一律用"可见外框"**。最大化/全屏时 `GetWindowRect` 会比屏幕每边多出约 11 px 的隐形 resize 边框。`rect()` 优先取 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`：中等窗口与 `GetWindowRect` 完全一致，最大化时自动收回到屏幕边。
4. **谁建的窗口谁抽消息**。Win32 窗口消息只由创建它的线程泵。`manager_step()` 跑在主线程 `WM_TIMER` 里，新建/销毁浮条窗口都不跨线程；`today_loop` 每轮先 `pump_msgs()`（`PeekMessageW` 抽干本线程队列）。建了窗口不抽消息 → Windows 判"程序未响应" → DWM 盖 `Ghost` 幽灵窗口，压在真窗口上点不掉，重启 WorkBuddy 也没用。**重活不进窗口线程。**
5. **坐标系别混**。`check_chat()` 里的 `sx` 是窗口相对坐标，喂给 `BitBlt` / `WindowFromPoint` 前必须加 `r.left`。
6. **抓来的像素必须验归属**，而且不能只靠 `WindowFromPoint`（见第 5 节的 `above_rects` 与 `EDGE_SHARP` 两道闸）。
7. **热重载靠自己退出，别加"自动重启"逻辑**。`reload_watch()` 检测到源文件变化就 `os._exit(0)`，由守护进程 1 秒后拉起；没有守护进程时才 `respawn_self(1.5)` 拉替身（延迟是为了避开自己还没放掉的互斥体）。这条线程一退出等于整个程序退出。

面板另有两个坑：`PANEL_CLASS` 必须独立于 `WND_CLASS`（共用时按类名枚举会抓到面板而不是浮条，测试满屏 FAIL）；`MEAS_DC` 在 `main()` 里建，离线渲染自己拉 `TodayPanel` 得先补 `B.MEAS_DC, _, _ = B.new_dib(1, 1)`，否则量字宽全返回 0、右对齐列被画到画布外。
